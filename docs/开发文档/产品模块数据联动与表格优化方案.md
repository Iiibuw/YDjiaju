## 一、产品数据表(MySQL 完整建表)

```sql
CREATE TABLE `products` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `product_code` VARCHAR(64) DEFAULT NULL COMMENT '产品编号(唯一)',
  `name` VARCHAR(128) NOT NULL COMMENT '产品标题',
  `subtitle` VARCHAR(255) DEFAULT NULL COMMENT '副标题',
  `series_id` INT UNSIGNED DEFAULT NULL COMMENT '系列 id → categories.id',
  `space_id` INT UNSIGNED DEFAULT NULL COMMENT '空间 id → categories.id',
  `category_id` INT UNSIGNED DEFAULT NULL COMMENT '品类 id → categories.id',
  `min_price_cents` BIGINT DEFAULT NULL COMMENT '最低价(分)',
  `max_price_cents` BIGINT DEFAULT NULL COMMENT '最高价(分)',
  `cover_url` VARCHAR(255) DEFAULT NULL COMMENT '封面图 URL',
  `other_images` JSON DEFAULT NULL COMMENT '其它图片(JSON 数组)',
  `description` TEXT COMMENT '产品详情(富文本 HTML)',
  `extra_specs` JSON DEFAULT NULL COMMENT '规格参数(JSON)',
  `support_order` SMALLINT NOT NULL DEFAULT 0 COMMENT '是否支持在线下单 0/1',
  `sort` INT NOT NULL DEFAULT 0 COMMENT '排序号(越大越靠前)',
  `status` ENUM('draft','on_sale','off_sale') NOT NULL DEFAULT 'draft'
           COMMENT 'draft草稿/on_sale在售/off_sale下架',
  `is_top` SMALLINT NOT NULL DEFAULT 0 COMMENT '是否置顶 0/1(草稿不可置顶)',
  `is_activate` SMALLINT NOT NULL DEFAULT 1 COMMENT '启用 0/1',
  `created_at` INT DEFAULT NULL COMMENT '创建人 id',
  `created_date` DATETIME DEFAULT NULL COMMENT '创建时间',
  `updated_at` INT DEFAULT NULL,
  `updated_date` DATETIME DEFAULT NULL,
  `deleted_at` DATETIME DEFAULT NULL COMMENT '软删除时间',
  `is_deleted` SMALLINT NOT NULL DEFAULT 0 COMMENT '软删标记',
  PRIMARY KEY (`id`),
  UNIQUE KEY `UNQ_products_product_code` (`product_code`),
  KEY `IDX_products_category` (`category_id`,`status`,`is_deleted`),
  KEY `IDX_products_series` (`series_id`,`status`,`is_deleted`),
  KEY `IDX_products_space` (`space_id`,`status`,`is_deleted`),
  KEY `IDX_products_status_top` (`status`,`is_top`,`sort`),
  KEY `IDX_products_created_date` (`created_date`),
  CONSTRAINT `chk_products_amount` CHECK (`min_price_cents` IS NULL OR `max_price_cents` IS NULL OR `min_price_cents` <= `max_price_cents`),
  CONSTRAINT `chk_products_draft_no_top` CHECK (NOT (`status` = 'draft' AND `is_top` = 1))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='产品主表';
```

索引设计要点:
- `(status, is_top, sort)` 支撑前台列表"按状态过滤 + 置顶优先 + 排序号"一条 SQL
- `(category_id/space_id/series_id, status, is_deleted)` 支撑三维筛选
- 价格用**分**(BIGINT),前端展示自动 `/100`

## 二、前后端联动逻辑(接口规范)

| 操作 | 接口 | 请求体要点 | 前台效果 |
|---|---|---|---|
| 新增 | `POST /admin/products` | `name*` `status*` `subtitle` `series_id` `space_id` `category_id` `min_price_cents` `max_price_cents` `cover_url` `description` `sort` | status=on_sale → 前台立刻可见(前端 30s 轮询/聚焦刷新) |
| 编辑 | `PUT /admin/products/{id}` | **部分更新**(exclude_unset,只改传入字段) | 改 name/价格/封面 → 前台同步更新 |
| 上架 | `PUT /admin/products/{id}` `{"status":"on_sale"}` | 仅 status | 前台立即出现 |
| 下架 | `PUT /admin/products/{id}` `{"status":"off_sale"}` | 仅 status | 前台立即隐藏 |
| 删除 | `DELETE /admin/products/{id}` | 软删除(is_deleted=1) | 前台消失 |
| 前台列表 | `GET /public/products` | 只返回 `status='on_sale' AND is_deleted=0`,支持 `category_id/space_id/series_id/keyword` | 草稿/下架永不展示 |

**关键修复点(本次)**:
1. 后台 PUT 从全字段 `ProductCreate` 改为 `ProductUpdate`(**部分更新**)——之前只传 status 会 422
2. 排序 `sort ASC → sort DESC`(数值越大越靠前)
3. 后台列表补 `space_name / series_name / category_name`(join categories)
4. 价格约束:前端表单校验 + 后端 `chk_products_amount` 双重保障;后端 service 抛 `ValueError → HTTP 400`
5. 前台 react-query:`staleTime:10s + refetchOnWindowFocus + refetchInterval:30s` → 后台改动后前台**自动刷新**,实现"实时同步"

## 二点五、分类管理(空间 / 系列 / 品类)

**表**:`categories`(单表三用,`type` 列 = 'space'/'series'/'category',自引用 parent_id 支持树形)

```sql
CREATE TABLE `categories` (
  `id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `type` ENUM('series','space','category') NOT NULL COMMENT '系列/空间/品类',
  `name` VARCHAR(64) NOT NULL COMMENT '中文名',
  `name_en` VARCHAR(64) DEFAULT NULL,
  `icon` VARCHAR(255) DEFAULT NULL,
  `parent_id` INT UNSIGNED DEFAULT NULL COMMENT '父级(树形)',
  `sort` INT NOT NULL DEFAULT 0 COMMENT '排序(大在前)',
  `status` SMALLINT NOT NULL DEFAULT 1,
  `is_activate` SMALLINT NOT NULL DEFAULT 1 COMMENT '启用0/1',
  `created_at` INT DEFAULT NULL,
  `created_date` DATETIME DEFAULT NULL,
  `updated_at` INT DEFAULT NULL,
  `updated_date` DATETIME DEFAULT NULL,
  `deleted_at` DATETIME DEFAULT NULL,
  `is_deleted` SMALLINT NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  KEY `IDX_categories_type_status` (`type`,`is_activate`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品分类(空间/系列/品类)';
```

**后端接口**(admin_categories.py 已实现):
- `GET  /admin/categories?kind=space` 列表(含禁用)
- `POST /admin/categories` `{kind,name,sort,enabled}`
- `PUT  /admin/categories/{id}`
- `DELETE /admin/categories/{id}`(被产品引用时删除失败 → 400)
- `GET  /public/categories?kind=` 前台只读(启用中)

**后台「分类管理」页**(`pages/Categories.tsx` 已上线,菜单第二位):
- 三个 Tab:空间 / 系列 / 品类,各自表格(ID/名称/排序/状态)
- 新增/编辑(Modal)、删除(二次确认)、启用禁用
- **产品表单的空间/系列/品类下拉**从该接口实时读取(不再手输)

**前台筛选栏**:`listCategories()` 动态渲染(空间/系列/品类三组),后台增删分类 → 前台自动同步(已实测:新增"书房" → 前台立即出现)

**产品「风格」字段**(表单新增):
- `products.style VARCHAR(64)`(v1.1 补充列,Model/schema/service/表单已同步)
- 前端表单为自由输入(如"现代简约"),可后续升级为分类表枚举

## 五、常见排查方案(前后台不同步调试步骤)

1. **查数据**:`SELECT id,name,status,is_deleted,sort FROM products;`
   - 前台不显示某产品 → 先确认 `status='on_sale'` 且 `is_deleted=0`
2. **直连接口验证**:
   ```bash
   # 前台列表(应只见 on_sale)
   curl http://localhost:8000/api/v1/public/products
   # 后台列表(含草稿/下架)
   curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/admin/products
   ```
   若接口数据正常但页面不同步 → 前端缓存问题
3. **前端缓存**:
   - 检查 react-query `staleTime`/`refetchInterval`(产品页已配 30s 轮询)
   - 硬刷 `Ctrl+Shift+R` 排除浏览器缓存
4. **后台操作后 422**:后台只传 `{status}` 更新 → 说明后端 PUT schema 是全字段(已改为 ProductUpdate 部分更新);若仍 422 看响应 detail 定位缺哪个字段
5. **前台筛选失效**:检查筛选参数名是否为 `space_id/category_id/series_id`(数字 id),前端 FilterPanel 传中文会被后端忽略
6. **排序不对**:确认 SQL `ORDER BY sort DESC`(历史代码是 ASC 已修复)
7. **Category 名称不显示**:后台列表 `space_name/series_name/category_name` 由后端 join categories 补出,若为 null → 产品行的 series_id/space_id/category_id 为空或分类被删
8. **日志**:后端 `uvicorn` 日志看 4xx/5xx + `unhandled_exception` traceback

## 六、联调测试步骤(已验证通过)

```bash
# 0. 前置:后端 8000、admin 5181、前台 5180 三服务在跑
#    登录拿 token(dev 验证码 ABCD)

# 1) 后台新增在售产品 → 前台立刻出现
curl -X POST localhost:8000/api/v1/admin/products \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"测试沙发","series_id":3,"space_id":1,"category_id":4,
       "min_price_cents":99900,"max_price_cents":199900,"status":"on_sale","sort":99}'

# 2) 后台下架产品 → 前台隐藏
curl -X PUT localhost:8000/api/v1/admin/products/{id} \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"status":"off_sale"}'
curl localhost:8000/api/v1/public/products   # 该产品消失

# 3) 后台新增分类 → 前台筛选栏自动出现
curl -X POST localhost:8000/api/v1/admin/categories \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"kind":"space","name":"书房","sort":9}'
curl "localhost:8000/api/v1/public/categories?kind=space"   # 含"书房"

# 4) 价格校验:低价>高价 → HTTP 400
curl -X PUT localhost:8000/api/v1/admin/products/{id} \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"min_price_cents":99999,"max_price_cents":1}'
# → 400 {"detail":"最低价不能大于最高价"}

# 5) 删除 = 软删除(前台立即消失,数据保留)
curl -X DELETE localhost:8000/api/v1/admin/products/{id} -H "Authorization: Bearer $TOKEN"
```
