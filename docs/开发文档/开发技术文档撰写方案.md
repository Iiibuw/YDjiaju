## 一、任务理解

根据 PRD 与 UI/UX 文档，产出一份**可落地开发的技术文档**，面向前后端工程师与 DBA，内容覆盖：

1. **系统总体架构** —— 前后端分离 + 双前端（前台 React+Tailwind / 后台 React+AntD）+ FastAPI 后端。
2. **数据库设计** —— 完整 ER 关系与数据字典（约 25+ 张表），含索引、数据隔离（多区域/多门店）设计。
3. **后端设计（FastAPI）** —— 项目结构、分层、鉴权（JWT + 图形验证码 + RBAC + 数据范围过滤）、审计日志、对象存储、支付预留。
4. **接口设计（REST API）** —— 约 60+ 个接口，含通用约定（分页/筛选/排序/错误码）与每个接口的详细契约。
5. **前端设计（React）** —— 前台/后台两个应用的项目结构、路由、状态管理、API 封装、设计 Token 落地与组件映射。
6. **开发流程** —— 环境准备、Git 规范、联调、测试、构建部署、里程碑任务拆解。

## 四、关键技术决策点（ADR 预览，正文将逐一展开理由与取舍）

| 决策点 | 推荐方案 | 备选 | 关键取舍 |
|---|---|---|---|
| 数据库 | **MySQL 8.0** | PostgreSQL 16 | 国内运维成熟、DBA 生态；PG 的 JSONB/全文检索更强但团队熟悉度低 |
| ORM/迁移 | **SQLAlchemy 2.0 + Alembic** | 原生 SQL / Tortoise | FastAPI 事实标准、可迁移、类型友好 |
| 认证 | **JWT（会员/后台双通道）+ 图形验证码** | Session Cookie | 双前端独立部署、无状态易横向扩展；图形验证码防爆破 |
| 前端组织 | **monorepo 双应用**（前台 + 后台） | 两个独立仓库 | 共享类型与请求层、统一版本；需 pnpm workspace 治理 |
| 数据隔离 | **管理员绑定区域/门店，服务端统一过滤** | 多租户 schema | 单库单 schema 成本低，API 层拦截防越权（PRD §7.3 强制） |
| 对象存储 | **抽象 Storage 接口**（OSS/COS/S3 可插拔） | 直连云厂商 | 本地开发用本地磁盘 mock，生产切云，降低联调依赖 |

## 五、撰写策略

- **单份 Markdown**（约 12000–18000 字）+ 可选 HTML 浏览版。
- **接口设计**为全文档重心：每个接口附**完整请求/响应 JSON 示例**与鉴权标注（参照 PRD 角色权限矩阵）。
- **数据库**以 Mermaid `erDiagram` + 数据字典表格呈现，关键表附字段类型/约束/索引说明。
- **架构**用 Mermaid C4 图（上下文 + 容器），避免过度设计——每个抽象都有 trade-off 说明。
- **代码示例**：附目录结构树 + 关键片段（如统一响应体、JWT 依赖、RBAC 装饰器、前端 request 封装、路由守卫）。

1. **数据库选型**：MySQL 8.0（推荐）／ PostgreSQL 16／由团队现有栈决定。
