## 2. 项目背景

### 2.1 业务背景
企业（家居制造/销售型品牌，品牌名"YD家具"）需要一套官方门户与配套后台，用于：品牌展示、产品营销、实景案例传播、招商与招聘引流、新闻发布，并支持**部分标准化商品的直接在线下单**，同时承接大量**咨询/预约线索**。参考站点蓝鸟家居（lanniao.cn）为典型"展示型官网"，其"企业介绍 / 产品系列 / 新闻资讯"模块被采纳为前台基础骨架；但本项目在其之上扩展为"展示 + 线索 + 部分电商"的混合模式，并补齐后台内容运营与权限治理体系。

### 2.2 项目目标
1. 建立统一的品牌官方门户，覆盖 PC 与移动端（响应式）。
2. 通过产品中心 + 实景案例提升转化与留资。
3. 支持部分商品在线下单，打通"浏览→加购→支付→订单"闭环。
4. 建立可运营的后台：内容、产品、订单、咨询、权限统一管控。

### 2.3 参考站点模块映射
| 蓝鸟家居模块 | 本项目去向 |
|---|---|
| 走进蓝鸟 / 关于我们 | 关于我们（关于YD、发展历程、品牌介绍）|
| 产品系列（按系列+空间）| 产品中心（系列+空间+品类三维筛选）|
| 新闻资讯 | 新闻（企业新闻 / 行业资讯）|
| （无）| 案例（独立实景案例栏目，新增）|
| （无）| 在线预约、在线客服、站内搜索、下载中心、招聘、多语言（新增）|

### 2.4 范围（In / Out）
- **In（一期包含）**：前台全部模块（含部分商品在线下单）、后台全部模块（仪表盘/轮播图/产品/案例/新闻/招聘/关于我们/预约/留言/订单/系统含权限）、多语言、移动端适配、统计看板、CMS 富文本 + 图片管理。
- **Out（本期不做）**：SEO 优化（详见 7.4）；完整会员营销体系、积分、优惠券、第三方商城对接、小程序/App 原生端。（注：规则/关键词智能应答客服已纳入本期，见 §5.9；生成式大模型 AI 客服仍为二期规划。）

## 4. 总体设计原则与技术栈

### 4.1 架构原则
- 前后端分离：FastAPI 提供 RESTful API，前台（React+Tailwind）与后台（React+Ant Design）均为独立前端应用，通过统一 API 网关交互。
- 后台管理的内容通过 CMS 富文本 + 图片上传沉淀，前台消费同一套数据接口。

### 4.2 技术栈
| 层 | 技术 |
|---|---|
| 后端 | Python 3.x + FastAPI（API/鉴权/业务）|
| 前台前端 | React + Tailwind CSS（展示系统，响应式）|
| 后台前端 | React + Ant Design（管理系统）|
| 数据存储 | 关系型数据库（产品/SKU/订单/用户）+ 对象存储（图片/PDF）|
| 鉴权 | 后台账号密码 + 图形验证码；JWT/Session 会话 |

## 5. 功能需求 · 前台展示系统

### 5.1 首页
- Banner/轮播图（后台配置；前台整张可点击，按后台"链接"字段跳转，可指向产品详情 / 案例 / 预约 / 产品中心等位置）。
- 推荐产品、最新案例、新闻头条区块。
- 顶部主导航：首页 / 产品中心 / 案例 / 新闻 / 招聘 / 关于我们（二级下拉：产品中心→全部产品/客厅精选/卧室精选/书房精选/茶室精选/办公家具；新闻→企业新闻/行业资讯；招聘→社会招聘/校园招聘；关于我们→关于YD/发展历程/品牌介绍/联系我们）。注：原"下载中心"一级入口已从顶部导航移除，仅保留在页脚快捷入口；产品中心下拉不再含"新案例展示"子项。
- 右侧操作区：站内搜索、在线预约、在线客服、购物车、会员登录。
- 页脚：关于/联系方式/友情链接/版权，含下载中心快捷入口。

### 5.2 产品中心
- 列表页支持三维筛选：**系列 / 空间（客厅·卧室·书房·茶室·办公·餐厅·玄关）/ 品类（床·沙发·衣柜…）** + 关键词。
- 产品详情页：图集、参数（材质/尺寸/风格/适用空间/是否定制/标签）、**价格、库存**、SKU 变体选择（颜色/尺寸/材质组合）。
- "最新案例"精选区块（引流至案例栏目）。
- **加入购物车 / 立即购买**（仅"支持在线下单"的产品显示购买按钮）。

### 5.3 案例（独立栏目 · 实景案例展示）
- 案例列表（按空间/风格筛选）+ 详情（实景图集、所用产品、户型/面积、描述）。
- 后台可维护案例与产品的关联。

### 5.4 新闻
- 列表分"企业新闻 / 行业资讯"两类，支持分页与搜索。
- 详情页富文本渲染。

### 5.5 招聘入口
- 社会招聘 / 校园招聘 两个列表，岗位详情 + 简历投递（表单留资，进入留言/线索库）。
- **我的投递与进度跟踪**：登录会员可在前台"我的投递"中查看已投递岗位及申请进度，进度分 5 个阶段——职位申请 → 简历筛选 → 面试考核 → Offer 签约 → 入职报到，按后台状态实时展示当前所处阶段；支持撤销申请。

### 5.6 关于我们
- 关于YD（企业/公司简介）、发展历程、品牌介绍、联系我们 四个单页/区块，后台富文本维护，支持中/英。
- **发展历程**：采用横向时间线视觉（"百年店"叙事，覆盖 1953 创立 → 历次里程碑 → 2026 现状 → 2053 愿景），节点卡片 + 渐变连接线，突出品牌历史厚度。
- **联系我们（新增）**：展示公司地址、销售热线（400-888-8888）、邮箱（contact@yd-home.com）、服务热线（400-888-9999）、社交媒体（微信/视频号/抖音/小红书）等联系方式，便于访客直接触达。

### 5.7 下载中心
- 产品画册 PDF 列表，点击下载（文件存对象存储）。

### 5.8 在线预约
- 表单：姓名/电话/需求类型/留言 → 提交后进入后台"咨询管理"（线索）。

### 5.9 在线客服
- 入口：顶部导航"在线客服"图标按钮 + 全站右下角悬浮客服按钮，点击均打开客服会话浮窗（原型已修复此前"点击无反应"问题）。
- 客服浮窗支持用户发送消息与**关键词智能自动应答**（覆盖价格/预约/售后/地址/电话/转人工等高频问题，详见 §13.1 #17），并支持常见问题快捷按钮；兜底为留资表单（已纳入本期范围，规则/关键词应答，非生成式大模型 AI 客服）。

### 5.10 站内搜索
- 全局搜索产品/案例/新闻，结果聚合页。

### 5.11 多语言（中/英）
- 本期不做（已纳入排除范围，见 §2.4 Out）。原型已移除语言切换入口，见 §13.1 #16。后续若恢复，需在内容与原型层重新接入双语字段。

### 5.12 购物车与结算/支付（部分商品）
- 购物车（增删改、数量）、结算页（收货信息、金额）、对接支付（微信/支付宝，预留）。
- **会员中心（轻量）**：为支撑订单可追溯，前台提供注册/登录、收货地址、我的订单、我的预约。*（假设：采用账号下单；若仅允许游客留资+下单可省略注册，默认账号下单。）*
- **登录态可视化**：会员登录成功后自动关闭登录弹窗，并以圆形用户头像替代"会员登录"按钮（原型已实现）；点击头像展开下拉菜单（个人中心 / 我的订单 / 退出登录），登录态持久化于本地。

### 5.13 移动端适配
- 全站响应式，移动端导航折叠、图片自适应、表单易用。

## 6. 功能需求 · 后台管理系统

### 6.1 登录
- 账号密码 + 图形验证码登录；会话管理；忘记密码（预留）。
- 登录成功后跳转至后台管理操作界面（默认进入"仪表盘"模块，渲染左侧菜单并展示对应模块内容）；会话过期/未登录访问后台受保护页面时重定向至登录页。

### 6.2 仪表盘 / 统计看板
- 核心指标卡：**访问量（PV/UV）**、**预约量**、**留言量**、订单量、销售额（趋势图）。
- 时间范围筛选。

### 6.3 轮播图管理（Banner Management）
- 管理首页及其它页面/位置（如产品中心顶部、案例详情推荐位）的轮播图。
- 字段：标题、图片、所属位置（首页 / 产品中心顶部 / 案例详情推荐位等）、跳转类型（产品 / 案例 / 新闻 / 预约等）、跳转参数（配合跳转类型定位目标，如产品ID / 案例ID）、排序、启用状态。*所属位置决定轮播图在前台的展示位；跳转类型 + 跳转参数决定点击后的跳转目标（产品详情 / 案例 / 预约 / 产品中心等）。（字段口径自 v1.2 起与《UI/UX 设计规格文档》§32 对齐：以"位置 + 跳转类型"取代原先笼统的单一"链接"字段。）*
- 支持增删改查、拖拽排序、批量启用/停用。

### 6.4 产品管理（Product Management）

- **分类管理**：系列、空间、品类 三类独立维护，支持树/标签。
- **产品管理**：增删改查；必填项 = **品类 或 适用空间 或 系列**（**v1.1 修订**：三选一至少其一，新增 `product_code` 作为对外稳定引用标识）；参数（材质/尺寸/风格/适用空间/是否定制/标签）；图集；是否支持在线下单开关。
- **SKU 管理**：颜色/尺寸/材质组合变体；每个 SKU 绑定**价格 + 库存**。
- **库存**：SKU 级库存，后台可调整。

**产品字段（v1.1）**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| **产品编号（product_code）** | string | ✅ | **v1.1 新增** · 全局唯一，作为对外引用标识（区别于自增 id），如 `YD-WT-001` |
| 产品名（name） | string | ✅ | 卡片 / 详情页标题 |
| 副标题（subtitle） | string |   | 卡片副标题 |
| 所属系列（series_id） | FK |   | 关联 `categories.type='series'`（如"胡桃禮"） |
| **所属空间分类 id（space_id）** | FK | ⭕ 三选一 | **v1.1 明确** · 关联 `categories.type='space'`（如客厅/餐厅） |
| 品类（category_id） | FK | ⭕ 三选一 | 关联 `categories.type='category'`（如实木餐桌） |
| 最低/最高价（min_price_cents / max_price_cents） | int (分) |   | 展示区间（不作为下单价） |
| **封面图片 URL（cover_url）** | string |   | **v1.1 明确** · 列表/详情封面 |
| **产品描述（description）** | richtext |   | **v1.1 明确** · 富文本 HTML，支持图片/视频 |
| **规格参数（specs_json）** | json |   | **v1.1 明确** · JSON 串，键值对，如 `{"主材": "黑胡桃", "尺寸": "1800×900×750mm"}` |
| **其它图片 URL（other_images_json）** | json |   | **v1.1 新增** · JSON 串，附属图数组 |
| 支持定制（is_custom） | bool |   | 是否支持定制下单 |
| 支持在线下单（support_order） | bool |   | 控制前台是否展示"立即购买"按钮 |
| 标签（tags） | json |   | JSON 数组，前台用于过滤 |
| **排序值（sort）** | int |   | **v1.1 明确** · 数值小者靠前 |
| **发布状态（status）** | enum | ✅ | **v1.1 三态枚举**：`draft` 草稿 / `on_sale` 上架 / `off_sale` 下架 |
| **是否置顶（is_top）** | bool |   | **v1.1 新增** · 用于发布列表"置顶优先"展示；草稿态不允许置顶（数据库 CHECK 约束） |

**列表筛选维度（v1.1 强化）**：

- 系列（series_id）、空间（space_id）、品类（category_id） 三维独立筛选，可任意组合
- 关键词（全文检索 name）+ 价格区间 + 是否可下单
- 默认按 `is_top DESC, sort ASC, created_date DESC` 排序

> **v1.1 与 v1.0 的核心差异**：
> 1. 新增 `product_code`（产品编号，唯一），作为对外引用标识
> 2. 新增 `other_images_json`（附属图 JSON）
> 3. 新增 `is_top`（置顶），与 `sort` 配合实现"置顶优先+排序"
> 4. `status` 由 `0/1`（上架/下架）扩展为 `draft/on_sale/off_sale` 三态
> 5. 数据库层 CHECK 约束：`chk_products_category_or_space`（三选一至少其一）、`chk_products_draft_no_top`（草稿不能置顶）

### 6.5 案例管理（Case Management）
- 案例增删改查、图集上传、关联产品、空间/风格标签、发布/下架。
- 支持内容维护。

### 6.6 新闻管理（News Management）

- 新闻增删改查、**v1.1 分类（企业新闻 / 行业资讯 两种）**、富文本、封面图、发布/下架。
- **v1.1 新增**：是否置顶 / 是否推荐 两种独立维度；发布窗口（发布时间 + 截止时间）；是否发布独立于业务启用状态。
- 支持内容维护。

**新闻字段（v1.1）**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| **标题（title）** | string | ✅ | **v1.1 明确** · 新闻主标题 |
| **分类（category）** | enum | ✅ | **v1.1 简化** · 仅两种：`corp` 企业新闻 / `ind` 行业资讯（原 `product` 产品资讯已合并/移除） |
| **封面图 URL（cover_url）** | string |   | **v1.1 明确** |
| **摘要（summary）** | string |   | 列表页/SEO 摘要，512 字符以内 |
| **正文（content）** | richtext | ✅ | **v1.1 明确** · 富文本 HTML（必填，可包含图片/视频/附件） |
| 作者（author） | string |   |  |
| **来源（source）** | string |   | **v1.1 明确** · 转载标注（"原创"/"来源 XXX" 等） |
| 浏览量（view_count） | int |   | 由前台访问累加 |
| **是否置顶（is_top）** | bool |   | **v1.1 明确** · 用于置顶优先展示 |
| **是否推荐（is_recommend）** | bool |   | **v1.1 新增** · 推荐位（与"置顶"独立，可同时为 true） |
| **是否发布（is_published）** | bool |   | **v1.1 新增** · 0 未发布 / 1 已发布；独立于业务启用状态，便于"内容已写好但暂未发布"的场景 |
| **发布时间（published_at）** | datetime |   | **v1.1 明确** · `is_published=1` 时必填 |
| **截止时间（expire_at）** | datetime |   | **v1.1 新增** · 默认 NULL 表示长期有效；非空时必须 ≥ `published_at` |

**前台查询规则**：

- 仅返回 `is_published = true` 且当前时间在 `[published_at, expire_at]` 窗口内的新闻
- 排序：`is_top DESC, is_recommend DESC, published_at DESC`

**后台维护界面**：

- 列表：标题 / 分类 / 摘要（截断 50 字）/ 发布时间 / 截止时间 / 是否发布 / 是否推荐 / 是否置顶 / 操作
- 表单：编辑器（标题、分类、封面、正文、摘要、作者、来源、发布时间、截止时间）+ 三个独立开关（发布/推荐/置顶）

> **v1.1 与 v1.0 的核心差异**：
> 1. `category` 由 `corp / ind / product` 三种简化为 `corp / ind` 两种（产品资讯合并到行业资讯）
> 2. 新增 `is_published` 字段（独立于业务启用状态）
> 3. 新增 `expire_at` 字段（发布截止时间）
> 4. 新增 `is_recommend` 字段（推荐位，区别于"置顶"）
> 5. 数据库层 CHECK 约束：`chk_news_publish_window`（截止 ≥ 发布时间）、`chk_news_published_has_date`（已发布必须有时间）

### 6.7 招聘管理（Job Management）
- 岗位增删改查、分类（社会招聘 / 校园招聘）、部门/地点/描述/状态维护。
- 简历投递查看与状态流转（待处理 / 已查看 / 已邀约 / 已淘汰）。
- **与前台进度对齐**：前台"我的投递"5 阶段（职位申请→简历筛选→面试考核→Offer签约→入职报到）由后台投递状态映射驱动：职位申请（已投递）→ 简历筛选（待处理/已查看）→ 面试考核（已邀约）→ Offer签约（已发Offer）→ 入职报到（已入职）。后台需提供阶段/状态维护字段，并向前台暴露进度。

### 6.8 关于我们管理（About Management）
- 作为一个整体单页维护，内含四个区块：关于YD、发展历程、品牌介绍、联系我们。
- 每个区块支持富文本、图集、时间轴条目维护。
- **发展历程**：维护横向时间线节点（年份/标题/描述/图标），覆盖品牌"百年店"叙事（1953 创立至 2053 愿景），前台以横向时间线渲染。
- **联系我们（新增）**：维护公司地址、销售热线、邮箱、服务热线、社交媒体账号等联系方式，前台"联系我们"区块展示。

### 6.9 预约管理（Appointment Management）
- 承接前台「在线预约」表单产生的线索：到店预约、产品咨询、定制需求、其它。
- 列表字段：姓名、手机号、需求类型、留言、来源页面、状态、跟进人、创建时间。
- 操作：分配客服、跟进记录、状态流转（待跟进 / 跟进中 / 已转化 / 无效）、导出。

### 6.10 留言管理（Message Management）
- 承接在线客服浮窗留言、招聘简历投递及其它非预约类留资。
- 列表字段：姓名、联系方式、来源（客服留言 / 招聘投递 / 其它）、内容、状态、跟进人。
- 操作：回复、标记状态、分配客服、导出。

### 6.11 订单管理（Order Management）
- 订单列表：状态（待付款/已付款/已发货/已完成/退款中/已退款/已关闭）、筛选、详情。
- 操作：发货、标记完成、退款处理、备注。
- 与支付/库存联动（下单扣库存、退款回库存，预留）。

### 6.12 系统管理（System Management）
- **站点信息配置**：名称、LOGO、联系方式、备案号、社交链接、多语言开关。
- **管理员与权限管理**：
  - 角色管理：超级管理员 / 内容编辑 / 产品管理员 / 客服运营 / 订单专员，可扩展。
  - 细粒度权限：按模块/操作（查看/新增/编辑/删除/导出）勾选授权。

  - 操作审计日志：记录关键操作（登录、增删改、权限变更、导出）的操作人/时间/对象/IP。
- **数据备份 / 导出**：数据库备份、内容/订单/线索导出。

## 7. 非功能性需求

### 7.1 移动端适配（必做）
全站响应式，移动端可用，关键转化路径（浏览/预约/下单）移动端闭环。

### 7.2 性能
- 官网类，常规并发；列表页首屏 < 2s（目标），图片懒加载、CDN/对象存储加速。

### 7.3 安全与合规
- 后台图形验证码防爆破；权限校验服务端强制执行（前端仅控制显隐）。
- 数据隔离在服务端按角色范围过滤。
- 操作审计留痕；用户隐私（手机号等）加密/脱敏存储，符合个人信息保护法。

### 7.4 SEO（本期不做）
明确不在一期范围：详情页 meta、sitemap、结构化数据（JSON-LD）均不实现，二期规划。

### 7.5 CMS 与媒体
- 富文本编辑（图文）；图片上传管理（对象存储、缩略图、分类）。

### 7.6 统计与可观测
- 访问量/线索量采集与看板；关键接口监控（预留）。

### 7.7 兼容性与可用性
- 现代浏览器（Chrome/Edge/Safari/Firefox）；后台以桌面操作为主但仍可响应式访问。

## 11. 风险与依赖
- **支付对接**：微信/支付宝需商户资质与回调联调（预留接口）。
- **图片/PDF 存储**：依赖对象存储（OSS/COS/S3）与 CDN。
- **多语言内容维护（若二期恢复）**：中英文双语内容需运营持续维护，成本较高。
- **数据隔离**：多区域/多门店权限需在 API 层统一拦截，避免越权。
